# Error Code Vocabulary (Plan 12+)

- **Namespace**: `errors` in `public/locales/{en,zh-CN}/errors.json`. Flat dictionary, 186 keys: 184 stable backend error-code strings + two catch-alls (`unknown`, `unknown_with_detail`).
- **Backend contract**: CGI scripts + daemons emit `{ error: "<code>", detail?: "<string>" }` (or `{ success: false, error, detail }`). Codes are stable snake_case tokens. Do NOT rename existing codes without a coordinated frontend sync — they are contract.
- **Frontend resolution**: use `lib/i18n/resolve-error.ts::resolveErrorMessage(t, code, detail, fallback)`. Tries `errors.<code>`; unknown code with detail → "Modem reported: {{detail}}"; no code → detail verbatim; else caller fallback.
- **Usage pattern** (any component with `t` in scope from any namespace):
  ```ts
  toast.error(resolveErrorMessage(t, res.error, res.detail, "Save failed"));
  ```
  The helper resolves via `{ ns: "errors" }` explicitly, so the caller's own namespace hook is fine — no second `useTranslation` needed.
- **`carrier_cid_protected`**: `cellular/apn.sh` save refused because the target CID holds an IMS/SOS context and the request lacked `allow_carrier_cid:true` (see [apn-management.md](apn-management.md)).
- **Adding a new code**: emit the snake_case string from the CGI → add one key to EN `errors.json` → add the zh-CN counterpart. `bun run i18n:check` enforces parity.
- **AT-commands namespace migration**: Plan 12 moved `system-settings.at_terminal.{commands,blocked_*,warning_disable_radio}` out into a new `at-commands` namespace (26 command labels + `blocked.*` + `warnings.*`). `BLOCKED_COMMANDS` / `WARNING_COMMANDS` `messageKey` values dropped the `blocked_`/`warning_` prefix; consumers resolve via `t(\`blocked.\${key}\`, { ns: "at-commands" })` / `t(\`warnings.\${key}\`, { ns: "at-commands" })`.
- **`sim_slot_switch_unverified`**: emitted by `cellular/settings.sh` when a SIM slot switch's `AT+QUIMSLOT=N` write cannot be confirmed via read-back after a full retry (`verify_quimslot()` — see [custom-sim-profiles.md](custom-sim-profiles.md)). Added to all 5 locales (en/id/it/zh-CN/zh-TW). Takes the `cgi_error` HTTP-200-envelope path like every other code here — never `success: true`.
- **SMS provider number (SMSC)**: `cellular/sms.sh` `set_smsc` emits `invalid_smsc` (not an optional `+` then 3 to 20 digits), `smsc_write_failed` (no `OK` from `AT+CSCA=` or the read-back failed) and, on `?action=smsc`, `smsc_read_failed`. All three are in the 5 locales. The same CGI also emits `missing_identities`, `missing_addr` and `command_failed`, which have no `errors.json` entry and resolve through the "Modem reported" catch-all. See [sms.md](sms.md).
- **`invalid_command`** (2026-10-19): qcmd and the broker refuse a line that is not an AT command (no case-insensitive `AT` prefix, or a control character) before it reaches the modem, and `at_cmd/send_command.sh` refuses it with a plain `detail`. Raw qcmd prints `ERROR: invalid_command` on stderr, rc 1. In all 5 locales; the AT Terminal also blocks it client-side with `at_terminal.rules.not_at`. See [at-broker.md](at-broker.md).
- **`modem_error` = the modem did not answer** (ledger B5.1). `cgi_at.sh::at_exec <cmd>` runs `qcmd` without a subshell, sets `AT_RAW` and returns 0 for a reply, **1 for a transport failure** (lock timeout or broker down: qcmd rc != 0 with empty stdout), and 2 for a modem `ERROR` / `+CME ERROR` (rc 0). A bare `*ERROR*` match reads rc 1 as success. CGIs answer 1 with `modem_error` and keep their feature code (`egmr_failed`, `autosel_failed`, `crsm_failed`, …) for 2. Read-only GETs whose payload would otherwise look empty ("no locks", an empty form) also error on 1. A display-only extra field (About's 3GPP release) degrades to empty instead. Converted: `ip_passthrough`, `mbn`, `imei`, `cellular/settings`, `network_priority`, `fplmn`, `frequency/status`, `network/dns`, `profiles/current_settings`, `system/known_sims` (clear refuses rather than dropping the inserted SIM), `at_cmd/reconnect_modem`, `device/about`. `frequency/lock`, `tower/lock`, `bands/lock`, `bands/current` and `scenario_mgr.sh` already checked rc and an empty reply. No new code was added.
- **`superseded_sim_changed`** is *not* an `errors.json` key — it is an internal `apply_status`/`apply_error` string written to `/tmp/qmanager_profile_state.json` by `qmanager_profile_apply`'s auto-mode stale-SIM guard when a newer SIM switch supersedes an in-flight profile apply. It never crosses the CGI error-envelope boundary this doc otherwise governs; the frontend never resolves it via `resolveErrorMessage`.
- **Live signal lease** (`cellular/live_signal.sh`): `bad_tier` (the `tier` query is not `aim` or `watch`) and `lease_failed` (run dir, lock, uptime, stamp or token could not be written; the detail is logged, not translated). Both are in all 5 locales and take the `cgi_error` HTTP-200-envelope path. A broker that cannot serve the feed is not an error: the CGI answers `{"success":true,"available":false}` and the UI stays on the 2 s tier. See [live-signal.md](live-signal.md).
