# Configuration Backup and Restore

CGI: `system/config-backup/{collect,apply,apply_status,apply_cancel}.sh` · Hooks: `use-config-backup.ts`, `use-config-restore.ts` · Types: `config-backup.ts` · Reboot: Deferred (dialog + banner for IMEI/profile)

- Route: `/system-settings/config-backup`. 13 sections in two picker groups (`lib/config-backup/sections.ts`): **Connection** (Network Mode + APN, LTE/5G bands, Tower Lock, TTL/HL, IMEI, Custom SIM Profiles) and **Monitoring and alerts** (Watchdog, Connection Quality (Sensitivity, targets and limits), Latency monitor sites, Prometheus Metrics, SMS Alerts, Message storage, Alert Routing).
- **Bands section** (`collect_bands`/`apply_bands`): captures/restores `lte_bands`, `nsa_bands`, `sa_bands` plus the failover flag. **NR-DC (`nrdc_nr5g_band`) is intentionally excluded** — the modem manages it and coerces manual writes, so it is neither backed up nor restored (see `docs/features/band-locking.md`).
- **Overlap rule**: Custom SIM Profiles is mutex with APN/TTL/HL/IMEI — profile activation owns those.
- **Encryption**: mandatory passphrase, AES-256-GCM, PBKDF2-SHA256 200k iters, 16-byte salt, 12-byte IV. Header bound as AES-GCM AAD via `canonicalHeaderAad()`. Passphrase never leaves browser.
- **Two engines, one format (ledger B5.33)**: WebCrypto when `crypto.subtle` exists, else `@noble/ciphers` (AES-GCM) + `@noble/hashes` (`pbkdf2Async`, yields to the event loop). `crypto.subtle` is undefined outside a secure context and the UI is normally reached over plain `http://`, so without the fallback Download failed and restore misreported a wrong passphrase. `defaultEngine()` picks; `deriveKey(..., engine)` returns an opaque `BackupKey` that encrypt/decrypt dispatch on. `getRandomValues` works in insecure contexts, so salt/IV are unchanged. `decryptPayload` throws `DecryptAuthError` only on a tag failure; `use-config-restore` maps only that to `password_incorrect`, everything else to `failed`. `crypto.test.ts` pins a known-answer vector (computed with `node:crypto`, key checked with Python `hashlib`) on both engines and cross-decrypts. Live 2026-10-18: HTTP backup (fallback) decrypted by `node:crypto`, HTTPS backup (WebCrypto) decrypted by the fallback.
- **File**: `.qmbackup` JSON envelope — plaintext header + base64 ciphertext (+ appended GCM tag). Filename: `qmanager-<model>-<YYYYMMDD-HHMMSS>.qmbackup` (UTC).
- **Section library**: `/usr/lib/qmanager/config_backup_sections.sh` — one `collect_<key>`/`apply_<key>` pair per section + `cfg_backup_{collect,apply}` dispatcher. Sourced by `collect.sh` CGI + worker. **Caller owns `qlog_init`**.
- **Apply order (fixed)**: `sms_alerts → alert_routing → sms_storage → connection_quality → sites → metrics → watchdog → network_mode_apn → bands → tower_lock → ttl_hl → imei → profiles` (`CFG_BACKUP_APPLY_ORDER`, `config_backup_sections.sh:48`). Safe first, reboot-queuing last. `alert_routing` sits next to `sms_alerts` (both trivial JSON writes) and re-clamps `connection_lost.email=false` on apply — see [`docs/features/alerts.md`](alerts.md). `connection_quality` precedes `watchdog` because the Watchdog's quality trigger reads its limits and an old `fail_threshold` converts at the restored Sensitivity.
- **`connection_quality`** (spec 3.1; formerly `quality_thresholds`, ledger B5.4): the Sensitivity, the four targets and the limits, as `{sensitivity, targets, latency_preset, loss_preset, latency_custom_ms, loss_custom_pct, alert_after_min}`. Collect reads `quecmanager.ping_profile.{sensitivity,targets}` and `quecmanager.quality_thresholds.*` (a device that still holds only the old `ping_profile.profile` collects that name as the Sensitivity). Absent presets are the default, so collect emits `null` and apply deletes them; presets travel as a pair (one alone is rejected). Apply re-validates every value: latency custom 1-10000 ms, **loss custom 1-100 %** (a backup carrying `0` is accepted and stored as `1`, with a warning in the log, because 0 % would breach on every probe), `alert_after_min` **1-1440** minutes (the one outage wait every alert channel uses; absent in the backup deletes it). A bad preset, custom value or wait fails the section; a bad `sensitivity` or `targets` (exactly four valid targets) skips just that key and leaves the device's own untouched, so an older backup without them keeps the current probe settings. Apply touches the ping, quality **and** watchcat reload flags (`/tmp/qmanager_ping_reload`, `/tmp/qmanager_quality_reload`, `/tmp/qmanager_watchcat_reload`). See [`connection-quality.md`](connection-quality.md).
- **Permanent fold-in (`cfg_backup_normalize`).** `.qmbackup` files outlive releases, so `apply.sh` runs the payload through `cfg_backup_normalize` before it validates section names: an old `quality_thresholds` section is folded into `connection_quality` (a key already in `connection_quality` wins) and removed, and the backup's Sensitivity is copied into the `watchdog` fragment as `_sensitivity` so an old `fail_threshold` converts at the backup's own interval. Never remove this shim.
- **Older releases refuse a new backup.** A backup that contains `connection_quality` fails on a release that predates the section with `unknown_section` (both at collect and at apply), because that release has no such key in `CFG_BACKUP_KNOWN_SECTIONS`. A backup taken on the older release restores fine on the new one.
- **`watchdog`**: UCI `quecmanager.watchcat.*`, 17 keys collected as strings: `enabled`, `act_after_sec`, `step_wait_sec`, `tier1_enabled`..`tier4_enabled`, `backup_sim_slot`, `max_reboots_per_hour`, `quality_enabled`, `quality_after_sec`, `ssr_aware`, `ssr_grace_sec`, `failback_enabled`, `failback_every_min`, `carrier_enabled`, `carrier_after_min`. Apply validates each non-empty value (booleans `0`/`1`/`false`/`true`; integers range-checked with no silent clamp: a bad value skips that key with a warning, never the section); an empty or null `backup_sim_slot` clears the slot, `1`/`2` set it, a missing key leaves it. **Old names translate permanently** with the install migration's formulas (`cqwd_migrate.sh`, so the two cannot drift): `fail_threshold` (or `max_failures`) x the probe interval -> `act_after_sec`, `quality_consecutive` x `check_interval` -> `quality_after_sec`, `cooldown` -> `step_wait_sec`, `ssr_grace` -> `ssr_grace_sec`, `primary_recheck_enabled`/`primary_recheck_interval` -> `failback_enabled`/`failback_every_min`; a new key in the backup wins over its old name, and the old names are read only on apply, never collected. `fail_threshold` converts at the backup's Sensitivity (the `_sensitivity` fragment above) or, without one, the device's current Sensitivity and override. Apply does not restart the daemon: it touches `/tmp/qmanager_watchcat_reload` and `/tmp/qmanager_poller_reload` (the poller gates its SA carrier read on `carrier_enabled`) and, when `enabled=1`, enables the service and starts it only if it is not running (a running daemon reloads from the flag); `enabled=0` stops and disables it. The SIM failover record and `crash.log` are device state and are not backed up. See [`connection-watchdog.md`](connection-watchdog.md#migration-from-the-old-keys).
- **`sites`** (ledger B5.4): `/etc/qmanager/sites.json`, mirroring `monitoring/sites.sh` save. No file = built-in defaults, so collect emits `{"default":true}` and apply removes the file. Apply re-validates every host (device `jq` has no regex: shell `case` check), clamps `interval_sec` to 60–3600, caps 32 sites, strips control chars from labels (max 40), dedupes by host, writes atomically, then nudges `qmanager_sites` (`/tmp/qmanager_sites_now`). See [`sites-monitor.md`](sites-monitor.md).
- **`metrics`** (ledger B3.7): UCI `quecmanager.metrics.{enabled,freshness}`, mirroring `monitoring/prometheus.sh` save; unchecked by default. **The bearer token is deliberately not in the backup**: a shared `.qmbackup` must not be able to scrape anyone's modem. Collect emits `{enabled, freshness}` (invalid or missing values read as `false` / `adaptive`). Apply re-validates both, and when `enabled` is true and the device has no valid token it generates one first via `qm_api_token_generate metrics` (from `api_auth.sh`; a failure aborts the section), then writes `enabled`/`freshness` and commits. It also keeps the poller's scrape file consistent: disabling removes `/var/run/qmanager/metrics_scrape`, otherwise the mode is rewritten with the uptime kept. Restoring an enabled section onto a device with no token therefore gives a **new** token the user must paste into Prometheus. See [`prometheus-metrics.md`](prometheus-metrics.md).
- **Async worker**: `/usr/bin/qmanager_config_restore` (double-fork via `apply.sh`). PID `/var/run/qmanager_config_restore.pid`; progress `/tmp/qmanager_config_restore.json`; input `/tmp/qmanager_config_restore_input.json`; cancel `/tmp/qmanager_config_restore.cancel`.
- **Retry**: 3 retries, backoff 1s/2s/4s, only on rc=1. rc=2 (unsupported) / rc=3 (SIM mismatch) bypass retries. Cancel checked between sections.
- **States**: `pending`, `running`, `retrying:N`, `success`, `failed`, `skipped:incompatible`, `skipped:not_in_backup`, `skipped:sim_mismatch`.
- **Deferred reboot (CRITICAL — QManager runs ON the modem)**: `apply_imei` writes IMEI via `AT+EGMR=1,7,"<imei>"` but does NOT `AT+CFUN=1,1`. `apply_profiles` writes `active_profile` marker but does NOT spawn `qmanager_profile_apply`. Both `touch /tmp/qmanager_config_restore.reboot_required`. Worker surfaces `reboot_required: true`. Frontend shows reboot AlertDialog + persistent banner (localStorage `qmanager_pending_reboot`). **One reboot total** — on next reboot, poller's boot-time `auto_apply_profile` picks up the marker, finds IMEI already correct.
- **UI (ledger U4.11.6, lucide route)**: two cards on `CARD_GRID` (`components/system-settings/shapes.ts`). Create backup: grouped section picker (Profiles disabled with a reason while APN/TTL/IMEI are on), passphrase + confirm, `CardFoot` with the selection count and Download. Restore from file: one card walking picker → passphrase (every backup is encrypted; a wrong passphrase stays on the step with an inline alert) → a 'Replaces your current settings' receipt (+ model-mismatch note) → Restore, all committed from `CardFoot`. The run is a Sequenced Pipeline Dialog (`restore-pipeline-dialog.tsx`, replacing `restore-password-dialog.tsx` and `restore-progress-list.tsx`): hero glyph, headline and determinate bar over a scrollable section ledger; not dismissible until terminal; Stop while running; capped at the viewport height. Toasts: one per terminal moment with a deterministic sonner id (success, partial with the failed count, cancelled, or a refused start through `resolveErrorMessage`); a backup download toasts success or the returned code. Reboot: `reboot_required` calls `requestRebootLater` (the app-wide deferred-reboot banner, `components/reboot/pending-reboot-banner.tsx` in `app-layout.tsx`; B5.19 — the page no longer renders its own), and closing the dialog opens the reboot AlertDialog (Later / Reboot now); the reboot handlers check `res.ok` (`authFetch` only throws on network errors) and fall back to the banner with an error toast.
- Guards: `apply.sh` returns 409 on active PID. `apply.sh`/`apply_cancel.sh` reject non-POST. 256 KiB cap via `CONTENT_LENGTH`.
- Cross-device: backup records `device.{model,firmware,imei}`. Browser compares `device.model` → `model_warning` state on mismatch. Appliers still silently downgrade unsupported items to `skipped:incompatible`.
- Profile auto-activation: ICCID match (`profile_iccid` vs `/tmp/qmanager_status.json::current_iccid`); mismatch → rc=3 → `skipped:sim_mismatch`, marker NOT written.
- Events (`dataConnection` tab): `config_backup_collected`, `config_restore_{started,section_success,section_failed,section_skipped,completed}`.
- Tests: `lib/config-backup/{crypto,format,sections}.test.ts` via `bun test`. Project's first Bun test setup — `tsconfig.json` excludes `**/*.test.ts` so `bun tsc --noEmit` doesn't choke on `bun:test` imports.
- TS 5.9 quirk: `crypto.ts` public API accepts bare `Uint8Array`; private `toFixedBuffer()` coerces to `Uint8Array<ArrayBuffer>` for `crypto.subtle.*`.
